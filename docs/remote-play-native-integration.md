**Status:** backend/client modules in progress; UI intentionally deferred  
**Base:** `fix/novelai-only-persistent-token-20261114` at `fc4a6618e7ae4e37a55ee9c679ef201634b72831`

This work adds Native Remote Host integration modules without changing the existing launcher home layout, NovelAI token storage/provider policy, Google Drive CloudSave flow, SAF tree registration, per-game WebView Origin, or per-game localStorage/IndexedDB.

## Module map

| File | Responsibility | Current boundary |
|---|---|---|
| `RemoteHostConnection.java` | QR manifest parsing, P-256 Host signature verification, Host identity and TLS-pin binding, signed approval receipt verification | No UI |
| `RemoteHostStore.java` | Stores signed Host metadata, selected logical root and stable Device ID; creates/reuses P-256 Android Keystore key | Bearer token is not persisted |
| `RemoteHostClient.java` | Pinned HTTPS transport, QR identity verification, Pairing proof, approval polling, 15-minute Device sessions, authenticated JSON/binary calls | No JavaScript credentials |
| `RemoteHostDiscovery.java` | Android NSD/mDNS rediscovery for an already QR-trusted Host; validates old TLS pin and fresh Host-signed URL before updating IP | Does not establish first trust |
| `RemoteHostMdnsCandidate.java` | Validates untrusted discovery metadata and private IPv4 candidates | TXT data alone is never trusted |
| `RemoteFilesClient.java` | Approved root listing, file download with Host SHA-256, sequential resumable upload, status, complete and cancel | Requires per-device file permissions |
| `RemoteGameResourceBridge.java` | Proxies game `/images/*` requests through pinned HTTPS, revalidates ETags and forwards Range | Only active when Remote PC image mode is selected |
| `RemoteResourceCache.java` | App-private image cache, exact ETag, bounded disk usage and duplicate in-flight request coalescing | 24 MiB/entry, 256 MiB total |
| `RemoteComfyClient.java` | Authenticated Host ComfyUI status, queue, workflow jobs, cancel, image upload/download | Requires `UseComfyUi`; does not start/stop the PC process |
| `tests/remote-play-contract.test.cjs` | Static contract checks for Host trust, session handling, WebView Origin, cache, ComfyUI and file-transfer boundaries | CI contract test, not network integration test |

## Connection and trust flow

1. A future UI scans the JSON QR generated by the Windows Manager and calls `RemoteHostClient.verifyAndStoreQr(context, qrJson)`.
2. The QR's Host Identity signature is verified before the certificate fingerprint is used as a TLS pin. The client then reads `/v1/host/identity` over pinned HTTPS and compares Host ID, public key and certificate fingerprint.
3. The first pairing call submits the Android Keystore P-256 public key. The client verifies the Host-signed challenge, signs the exact payload, and waits for a Windows Manager approval.
4. The approval receipt is checked against the expected Host ID, Pairing ID, Device ID, public-key fingerprint and permission bitmask. A mismatch fails closed.
5. Each subsequent session is acquired with a new Host-signed challenge. The token stays in process memory and expires after 15 minutes.
6. mDNS rediscovery is available only after QR trust. The discovered TXT record must match the saved Host ID/key/certificate fingerprints. The client then connects using the previously saved certificate pin and checks a fresh signed manifest before persisting a new private IPv4 URL.

The mobile client never connects directly to PC port 8188. ComfyUI requests use the authenticated Remote Host gateway only.

## WebView and storage preservation

The official launcher continues using its current `https://localhost:<profilePort>` per-game WebView Origin. No Host URL, bearer token, Device private key, pairing polling secret or ComfyUI credential is passed to game JavaScript. The existing WMLHost bridge is unchanged.

The Native image interceptor sends only the encoded game image path to `/v1/game/images/...` under the previously selected logical root. The PC Host remains responsible for its allow-listed directory boundary, MIME type, ETag, conditional GET and Range handling. Android stores bounded cache files under the app cache directory and validates the exact cache ETag before reusing cached bytes.

The bridge does not change SAF local folder access. When Remote PC mode is not selected, the original SAF/ZIP-mod image path remains the fallback. The existing NovelAI image-generation mode remains separate.

## File operations

- `RemoteFilesClient.list` returns the Host-approved root's logical items.
- `RemoteFilesClient.openDownload` returns a streaming response and requires a valid Host SHA-256 header.
- `beginUpload` returns the Host upload ID and maximum chunk size.
- `appendUploadChunk` uses the exact Host-reported sequential `Upload-Offset` and a maximum 1 MiB chunk.
- `getUploadProgress` queries the authoritative offset after reconnect or process restart.
- `completeUpload` asks the Host to verify final length/hash and atomically place the file.
- `cancelUpload` cancels a session owned by this Device.

The Host decides whether the Device has `BrowseGameLibrary`, `ListFiles`, `DownloadFiles` and `UploadFiles` permissions. Default pairing permissions are read-only.

## ComfyUI operations

The Native Comfy client supports:
- system status, installed node info and queue;
- workflow submission and Prompt ID tracking;
- history lookup and job cancellation;
- streaming input image upload;
- output image download and app-private cache keyed by Host + Prompt ID + file identity.

Generated image cache files have a SHA-256 sidecar and must pass a hash check before reuse. The PC Host still owns the only upstream connection to `127.0.0.1:8188`. Mobile process start/stop/restart is not available in API v1; the Windows Manager remains responsible for ComfyUI process lifecycle.

The Native Comfy API is not yet connected to the existing game's ImageGen response contract. It does not alter the NovelAI-only local ImageGen server.

## UI deliberately not included

No Remote Play home tile, settings Activity, camera permission, QR scanner dependency, new button location or screen layout is included. The user has reserved the final UI design for a separate instruction.

When the UI design is supplied, the new Activity/screen should call these Native modules. It should not duplicate QR verification, certificate pinning, session management, file API or ComfyUI transport. The UI must use the existing serialized `ImageServerModeCoordinator` and `RemotePcServerControl` contract, then invoke `switchToRemotePcServer()` only when the selected Host/root has been validated.

## Current verification limits

- Android GitHub Actions validates the official launcher scope, NovelAI and Google OAuth regression contracts, Remote Play security/API contracts, Debug/Release APK builds, Release signature identity and Android 15 emulator app startup.
- These tests do not prove a real Windows Host connection, PC mDNS on physical Wi-Fi, QR scan, Manager approval, file download/upload, game image rendering or actual ComfyUI inference.
- No physical Android device / Windows PC session has been completed by these repository-only tasks.
- The official Home screen remains unchanged until the user provides the UI design.
