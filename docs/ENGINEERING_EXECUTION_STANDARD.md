# 공통 개발 실행·검증·검수 표준

이 문서는 이 저장소의 모든 분야·작업 브랜치에 적용되는 운영 규칙이다. 프로젝트별 구현 요구사항이나 담당 분야별 설계 지시를 대체하지 않는다. 별도 지시가 충돌하면 사용자가 명시한 최신 범위와 승인 조건을 우선한다.

## 1. 역할 분리

### 구현 담당자
1. 지시된 범위의 코드와 필요한 문서 수정
2. 구문·정적 분석·컴파일 오류 확인 및 수정
3. 변경한 코드의 직접적인 호출·이벤트·데이터 흐름 연결 확인
4. 변경에 필수적인 최소 단위 테스트와 필수 빌드 실행
5. 보안, 데이터 손실, 마이그레이션, 기존 기능 손상 위험이 있는 변경의 직접 검증
6. 수정 파일, 커밋, 빌드·테스트 결과, 미해결 사항만 간결하게 보고

구현 담당자는 전체 레포 회귀 검증, 전체 UX 재검수, 변경과 무관한 기존 기능 재검증, 최종 통합 검수를 중복 수행하지 않는다.

### 분야별 총괄 참모 / 최종 검수 담당자
1. 구현 지시가 요구사항과 승인 범위를 정확히 반영하는지 관리한다.
2. 구현 결과와 실제 diff·커밋·검증 증거를 대조한다.
3. 통합 영향, 기존 기능 회귀, 분야 간 계약·호환성 및 UX를 검수한다.
4. 구현 담당자가 이미 수행한 검증을 이유 없이 반복하지 않는다. 필요한 경우 결과를 재사용하고, 위험이나 증거 부족이 있는 항목만 표적 재검증한다.
5. 결함은 재현 조건, 근거, 수정 범위를 특정해 구현 담당자에게 전달한다.
6. 최종 승인·병합·배포는 사용자의 승인 권한과 프로젝트별 지시를 따른다. 승인 없이 main 병합, 릴리스, 배포하지 않는다.

## 2. 검증 단계와 중복 방지

- **구현 단계:** 변경분의 구문/컴파일, 직접 연결, 필수 최소 테스트·빌드만 수행한다.
- **통합 검수 단계:** 총괄이 diff와 계약을 검토하고, 변경 영향에 비례해 통합·회귀 검증을 선택한다.
- **최종 단계:** 필요한 전체 CI 또는 전체 회귀 검증은 통합 검수 담당자가 판단해 수행한다. 이미 동일 커밋·동일 환경에서 통과한 결과가 유효하면 불필요하게 다시 실행하지 않는다.
- CI가 변경되지 않은 영역까지 광범위하게 검사하거나 시간이 오래 걸리는 경우, 변경 영향과 기존 결과를 먼저 확인하고 필요한 작업만 실행한다.
- 검증을 생략한 경우에는 생략 이유와 미검증 범위를 명시한다. 실행하지 않은 테스트를 통과했다고 보고하지 않는다.
- 실패한 필수 검증은 원인을 확인하고 수정한 뒤 필요한 범위에서 재실행한다. 단순히 성공 결과를 만들기 위한 테스트 삭제·비활성화·범위 축소는 금지한다.

## 3. 범위·기능 보존 원칙

- 지시된 요구사항만 최소 변경으로 구현한다.
- 검증 완료 기능, 무관한 모듈, 다른 분야의 저장소·브랜치·코드는 임의로 수정하지 않는다.
- 리팩터링, 의존성 교체, 포맷 전체 변경, 파일 이동, 추가 기능은 명시적 필요와 승인 없이 하지 않는다.
- 기존 데이터·사용자 설정·자산·인증 정보·페어링·저장 형식은 호환성과 보존을 우선한다.
- 보안·개인정보·권한·네트워크·저장소 변경은 실제 동작과 실패 경로를 최소한 직접 확인한다.
- 요구사항이 모호해도 독립적으로 진행 가능한 부분은 중단하지 않는다. 사용자 결정이 반드시 필요한 충돌·파괴적 변경만 구체적인 선택지와 함께 질문한다.

## 4. 브랜치와 변경 관리

- 작업 시작 시 저장소, 현재 브랜치, 기준 커밋, 작업 범위를 확인한다.
- 지정된 작업 브랜치에서만 작업하고, 다른 분야의 브랜치나 저장소를 임의로 수정하지 않는다.
- 기존 작업물을 덮어쓰거나 force push하지 않는다. 충돌 시 현재 상태를 확인하고 보존한다.
- 커밋은 변경 목적이 분명하도록 작성하고, 보고에 커밋 SHA와 수정 파일을 포함한다.
- 병합·릴리스·배포는 별도 승인 없이 수행하지 않는다.
- 브랜치별 문서는 공통 표준의 사본이다. 공통 표준 변경 시 해당 작업 브랜치에도 같은 내용을 동기화한다.

## 5. 완료 보고 형식

구현 담당자는 아래 항목만 간결하게 보고한다.
- 저장소 / 브랜치 / 기준 커밋
- 변경 파일과 핵심 변경점
- 커밋 SHA
- 수행한 구문·컴파일·빌드·필수 테스트 결과
- 미수행 검증과 그 이유
- 남은 위험 또는 차단 사항

총괄 검수 담당자는 별도로 요구사항별 판정, diff 근거, 표적 재검증 결과, 미해결 결함, 승인 여부를 보고한다.

## 6. 최우선 원칙

속도는 불필요한 중복 작업을 제거해 확보한다. 필수 검증·보안 확인·데이터 보존을 생략해 속도를 내지 않는다. 구현 담당자와 최종 검수 담당자의 책임을 분리하고, 각 단계는 자신에게 필요한 증거만 생산한다.
